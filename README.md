# 顺手（shunshu）

监控小说**目录页**有没有更新的小工具。Windows 托盘常驻，没有窗口界面：添加、删除、改间隔、看状态全在托盘右键菜单里，更新提醒用右下角卡片。

只做一件事：抓目录页 → 认出章节容器 → 比对新旧章节 → 有更新就弹卡片。正文一律不下载，点章节交给默认浏览器打开。

## 快速开始

双击项目根的 **`启动.bat`**：后台起托盘，不留控制台窗口；首次运行会自动 `uv sync` 装依赖。排错用 `启动.bat debug`（带控制台启动，异常直接看得见）。

重复双击不会多出第二个图标——第二个实例会弹一张「顺手已经在运行」的卡片然后自己退出。

手动启动（与双击等价，会占着控制台）：

```bat
uv sync
uv run shunshu
```

开机自启：托盘菜单勾「开机自启」（写 HKCU 的 `Software\Microsoft\Windows\CurrentVersion\Run`，用 `pythonw.exe` 起，不占控制台）。

添加小说：在浏览器里复制目录页网址 → 托盘「添加小说（从剪贴板）」。抓完直接弹一张卡片，列出**最新的 5 章**让你确认认对了书（顺手点一章就能开始看，并记为已读）；书名从页面标题里取，这一轮只记基线、不算更新。

## 托盘菜单

- **小说列表** → 每本一个子菜单：`打开最新章节`（跳浏览器并记为已读，跨来源取最新的那一章）、`立即检查本书`、`添加来源到本书（从剪贴板）`、`暂停/恢复本书`、`删除本书`（要先点一次「确认删除本书？」）；识别失败时还会给出候选容器文件路径。
- **来源子菜单**：书下面逐个列出该书的**来源**，行上写着站点、状态、（手写过代理时的）代理地址，主源那行标「（主源）」。点开某一源：第一行是它的目录页网址，然后是最后一章与章节数、**这一源实际走的代理**（`跟随系统 http://127.0.0.1:7890` / `手写覆盖` / `当前没有系统代理，直连`），再往下是 `设为主源`（已经是主源时灰着）、`暂停此源 / 恢复此源`、`删除此源`（同样点两次确认）。删掉最后一个来源等于把整本移出书架。
- **添加小说（从剪贴板）**：从剪贴板文本里提 http(s) 网址；同一网址重复添加会提示。
- **重新加载配置**：手改过 `data/novels.json` / `data/config.json` 后点这里生效，不用重启。
- **立即检查全部**：跑一轮，结果按书各弹一张卡片。
- **扫描间隔**：5 / 10 / 30 / 60 分钟，四选一，默认 30 分钟（固定间隔，不做抖动）。
- **开机自启**：勾选状态即当前注册表项是否存在。
- **打开数据目录** / **退出**。

## 更新卡片

一个弹窗只说一本书。这本书挂了多个来源时，**同一次检查里几个来源各自更的章会合成一张卡**，卡片固定列**最近的 5 章**（不管这次更新了几章），按章节顺序从新到旧排：

- **绿色** = 没读过；**灰色** = 已经点开过。用来确认自己有没有漏看。
- 每行右边标出**这一章是最先由哪个来源报上来的**（谁先更就归谁），标题写成「《书名》更新 N 章（来自 A、B）」；更的章只有镜像站报了、主源没报，标题会再加一句「主源未更新」。
- **同一章只提醒一次**：镜像站报过「第61章」之后主源才更出同一章，不会再弹第二遍（繁简站标题不同也算同一章）。
- 点任意一章：交给默认浏览器打开，该章记为已读，卡片自己收起。
- 点「关闭」：只收起卡片。12 秒没人理它也会自动消失。

刚添加一本时弹的是同一种卡片，标题换成「已添加《书名》」，列最新的 5 章（此时都还没读过，全绿）。往一本已有的书里**追加来源不会再多弹一张卡**——那张卡是该书第一次进书架时弹的。

「已读」的判定就是**你通过本工具点开过这一章**（卡片上点的、或托盘里点「打开最新章节」）。工具不下载正文，所以没法知道你在浏览器里读过什么——直接在网站上看的章节不会变灰。

## data/ 目录

运行时生成在项目根（打包后在 exe 同级）：

| 文件 | 内容 |
| --- | --- |
| `novels.json` | 书架。每本小说一段：`title`、`primary_id`（主源）、`read_keys`（点开过的章节，**跨来源共用**）、`alerted_keys`（已经弹过卡的章节，跨来源共用，重启后靠它不重复弹）、`chapter_index`（最近若干章的索引：章节号、标题、URL、最先报它的来源，卡片就按这个排）、`sources`（这本书的所有来源）。每个来源有自己的 `toc_url`、`site`、`selector`、`proxy`、`keep_keys`/`drop_keys`、`notified_keys`（本站已提醒过的章节）与状态。可手改，改完走「重新加载配置」 |
| `config.json` | 抓取与广告名单，缺省即内置默认值 |
| `history/<novel_id>/<source_id>.jsonl` | 按来源分开存的检查记录：`baseline` / `update` / `toc_reset` |
| `candidates/<source_id>.txt` | 识别失败时导出的候选容器与被过滤链接 |
| `filtered.log` | 每轮被当成广告丢掉的链接（原因 + 文本 + URL） |
| `alerts.log` | 每次弹窗的内容与跳转地址 |
| `read.jsonl` | 卡片进程写的已读记录（`novel` + 跨源章节身份 `key`），主程序下一轮吸收进 `novels.json` 后清空 |
| `shunshu.log` | 运行日志，一轮一行 |

`version` 为 2。**一本挂多个来源**日常走托盘「添加来源到本书（从剪贴板）」，直接手改也行：在同一本小说的 `sources` 数组里追加一项，`id` 用目录页 URL 的 sha1 前 12 位。不同站点、繁简站混着放都行——同一章在各来源上会归一到同一个跨源身份，已读与提醒都按这个身份合并。

## 代理怎么配

**默认不用配**：来源没写 `proxy` 时，抓取走的就是**系统代理**，和浏览器同一套（环境变量 `HTTP_PROXY`/`HTTPS_PROXY` 与 Windows 的 LAN 代理设置，`no_proxy` 绕过表照样生效）。你的代理程序开着「系统代理」，本工具就直接跟着走，不需要任何设置。

`proxy` 字段是**覆盖**，只用于「这一源要单独走另一个代理」的情况（比如繁简站要代理、主源直连更快）。写在 `data/novels.json` 里该来源那一项上：

```json
{
  "id": "3f2a1c9d8b70",
  "toc_url": "https://繁体站.example/12_3456/",
  "proxy": "http://127.0.0.1:7890"
}
```

只接受 `http://`、`https://`、`socks5://` 三种前缀，必须带协议名；`socks5://用户:密码@127.0.0.1:7890` 这种带账号的写法也有效，但显示与日志里只会留 `socks5://127.0.0.1:7890`，凭据不落盘。改完托盘点「重新加载配置」。

**想知道某一源实际走了什么**：托盘 → 该书 → 该来源，子菜单里那行「代理 …」就是结论——没写覆盖时显示当前生效的系统代理地址，没有系统代理就写「直连」。设置入口仍然只有 `novels.json` 这一处，菜单只负责显示。

抓不动时状态会分得很清：

- **代理不可用**＝代理本身不通（代理软件没开、端口写错、忘了带协议前缀）。这类错误不会重试三次浪费一轮，直接记一次失败并进入退避；原因原话（例如 `[WinError 10061] 由于目标计算机积极拒绝`）就写在这本书该来源的那一行里，托盘菜单直接看得到。
- **网络错误**＝代理/网络是通的，站点自己没响应（超时、断链、HTTP 4xx/5xx）。
- **解析失败**＝页面抓到了但认不出章节容器，去看 `data/candidates/<source_id>.txt`。

## 识别失败怎么修

盗版站改版后可能认不出章节容器，托盘里该书会显示解析失败原因。步骤：

1. 打开 `data/candidates/<source_id>.txt`，里面按得分列了候选容器的 CSS、链接数、章节样式数、广告数和样例。
2. 挑最像的那个，把它的 CSS 填进 `data/novels.json` 里该书 `sources` 中这一项的 `"selector"`（填**容器**，不是单条链接），例如 `"selector": "div.listmain dl"`。
3. 托盘「重新加载配置」→「立即检查本书」。
4. 误杀章节：把该章 URL（或标题）填进该来源的 `keep_keys`；漏进来的广告：填进 `drop_keys`。两者都支持归一化 URL、原始 URL、标题三种写法。

内置的判定不是「必须有第X章」：章节号支持中文数字与 `1001.` 形式编号，倒序目录、分页目录都能处理——有「末页」跟末页，只有「下一页」的两页站也跟着翻一页，只认同目录下的翻页链接，`/module.php?go=next` 这类假翻页不敲。一次冒出过多新章节、或已知章节大面积消失，会判为「目录被重置/整站改版」并记录但**不提醒**，避免把整本书当新章节刷屏；刚开始多跟到一页时不算重置，那批新章是真新章。

## 打包成 exe

CI 在 `.github/workflows/build.yml`：push 到 `main` 用 Nuitka 编出 standalone 目录并上传 Artifacts，打 `v*` tag 额外把 zip 挂到 GitHub Release。同一个 `shunshu.exe` 兼任两件事——直接运行是起托盘，`shunshu.exe popup --payload <json>` 是主程序弹卡片时调的子命令（因此打包态判定要认 Nuitka 的 `__compiled__`，见 `notify.popup_command`）。编译参数以 workflow 里那条为准，本地跑同样的命令即可（需要先 `uv sync --group dev`）。

## 设计与取舍

- **入口只有两个**：托盘右键菜单，和直接改 `data/*.json`。不提供命令行——`shunshu` 这个命令只做一件事（起托盘），`python -m shunshu popup` 是主程序弹卡片时自己调用的内部子命令。
- **不用 Windows 原生 toast**：非打包进程在这台机器上注册不了 AUMID，WinRT 的 `Show()` 不报错但通知会被静默丢掉。所以卡片是自己用 Tk 画的、由短命子进程弹出的无边框窗口（`python -m shunshu popup --payload <json>`）。
- **只放行 http(s)**：任何要交给 shell / 浏览器的 URL 都先过 `assert_http_url`，`javascript:`、`data:`、本地路径一律拒绝；卡片里显示的跳转地址也会先过滤再写日志。
- **跳板链接不在服务端跟随**：`/b.php?url=...` 这类章节链接原样保留，交给浏览器完成跳转，少一次请求就少一次风控暴露。
- **同站串行 + 间隔**：并发只用于不同站点（默认 6），同域名单线程并留 2 秒间隔；响应体大小、超时、重试退避都有上限。
- **编码**：盗版站大量 gb18030，按 header → meta → utf-8 → gb18030 的顺序定编码，声明 gb2312/gbk 的一律按 gb18030 解。
- **最新章节按目录自己的排列定**：把抓到的章节按目录出现顺序排成旧→新，再用相邻编号的升降投票判断这本书是正序排还是倒序排（倒序站取开头，正序站取末尾）。**站点自己把编号写乱时不猜编号**——有的站正文排到 1564 章，末尾又另挂一块 184~190 章，那块才是最新，按编号取就永远取错。跨来源比较仍按章节号（同源的乱序只在源内按排列解决）。
- **TLS 用 Windows 系统证书库**：盗版站常常只发叶子证书、少发中间证书，浏览器会自己补链，certifi 不会，于是浏览器能开的站在工具里报 `CERTIFICATE_VERIFY_FAILED`。抓取器启动时把默认证书库换成系统库（`truststore`），代理软件自签的 CA 装进系统库也就跟着信；换不了就退回 certifi，不会更差。**验证没有关掉**，只是换成本机信得过的那套根。
- **章节身份**：来源内去重用 `normalize_chapter_url` 归一化后的 URL（协议统一 https、去 www、去 index.html 与尾斜杠、去 fragment 与跟踪参数、去默认端口，业务参数保留）。改名、换协议都不会重复提醒。
- **跨来源认同一章**：用「章节号 + 正题」的 `match_key`——正题先转简体、剥掉「第X章/1001.」序号前缀与「（求月票）」这类括号标注，只留汉字数字和小写字母再比对。繁简两个来源的「第120章 風雪夜歸人」和「第120章 风雪夜归人」因此认得出是同一章，已读状态共通：在一边点开过，另一边那张卡片里也是灰的。**显示也统一成简体**——卡片、托盘菜单里都是简体，但 `data/history/` 与 `novels.json` 存的是源站原文，跳过去的网页仍是繁体原样。
- **状态分两层**：`notified_keys` 按来源记（各站 URL 不同），`read_keys`、`alerted_keys`、`chapter_index` 与书名按小说记；书名以最先抓到的来源为准，之后不再改写。
- **提醒按小说记，抓取按来源记**：一轮里各来源的新章先按来源自己的 `notified_keys` 判新，再用 `match_key` 在小说级去重后合成一张卡。卡片只列最近几章，索引默认留 50 章。记账与弹卡是分开的两步：先按小说级去重把这一轮的章节记进 `alerted_keys`，再决定弹不弹，所以卡片没弹成（子进程起不来、被系统丢掉）也不会漏记，同一章不会再来一遍。
- **`notified_keys` 先记全目录，再记历史**：`notified_keys_keep`（默认 500）只裁**已经不在目录里**的历史 key，目录还列着的章节一个都不能忘——一本 1600 章的书要是被裁掉一半，下一轮就会把那 800 章全当成新更新，永远卡在「疑似重编号」里出不来。
- **新来源的基线不算更新**：中途挂上来的慢镜像首轮只建基线，那批章节直接并进 `alerted_keys`，所以主源几周前就报过的章不会被它当成新章刷屏。
- **默认跟随系统代理，`proxy` 只是覆盖**：不写 `proxy` 时 requests 走的就是浏览器那套系统代理（`Session.trust_env`），代理程序开着就不用配。写了 `proxy` 只让该来源单独走指定代理，另一个来源照常——繁简站常常一边要代理一边不要。代理不通单独记 `代理不可用`，不重试、不跟「解析失败」混在一个状态里；交给日志与托盘的代理地址一律去掉账号密码。来源子菜单里那一行「代理 …」显示的是**实际生效**的结果（手写覆盖 / 系统代理地址 / 直连），设置入口仍只有 `novels.json`。
- **失败退避**：某个来源连续失败 5 次后跳过若干轮，成功即清零；一个来源挂了不影响同一本书的其它来源。

## 测试

```bat
uv run pytest tests -q
```

154 个用例，全用内存假站点（`tests/fixtures.py` 里的正常页/gbk 页/倒序页/分页页/广告堆页/跳板页/纯编号页），不联网、不弹真卡片也不起真 Tk 窗口（`tests/conftest.py` 里 autouse 把 `spawn_card` 换掉了，卡片点击逻辑用 `FakeRoot` 测）。代理相关的用例把 `Session.get` 换成假函数，因此也不真连代理。

## 变更记录

- **0.6.2（2026-10-10）**：编译版的卡片终于弹得出来。Nuitka 会把 `sys.executable` 伪造成产物目录下的 `python.exe`（**那个文件并不存在**，真实路径在 `sys.argv[0]`），于是 `Popen` 报 `WinError 2` 而被 `except OSError` 静默吞掉——托盘在跑、日志在写，就是没有卡片。现在打包态判定改成「argv[0] 是文件而 executable 不是」，起进程失败时把异常与实际命令写进 `alerts.log`，不再静默。已本地按 CI 同款参数编译并截图验证：启动检查卡正常弹出。
- **0.6.1（2026-10-10）**：把 exe 真编出来跑通了。Nuitka 在 CI 非交互模式下会因「能否下载 Dependency Walker」默认答 no 而 FATAL，加 `--assume-yes-for-downloads`；入口改传包目录 `src/shunshu`（产物目录随之变成 `shunshu.dist`，CI 里 zip 那步的路径也跟着改）；`__main__.py` 被编译成顶层脚本后相对导入会 `ImportError`，加绝对导入兜底；打包态判定不再单靠 `sys.frozen`/`__compiled__`（Nuitka 只给入口模块注入），改用可执行文件名兜底，并加 `--no-deployment-flag=self-execution` 作为保险。
- **0.6.0（2026-10-10）**：启动与打包态修好。`启动.bat` 改成纯 ASCII——之前被另存成 UTF-8 又在文件里 `chcp 65001`，cmd 按字节偏移续读 .bat 会跳歪，把注释碎片当命令执行（`'nshu' 不是内部或外部命令`），脚本其实一次都没跑起来；`run_forever()` 去掉重复的首轮，之前每次启动把所有站点连敲两遍；打包态判定补上 Nuitka 的 `__compiled__`（只认 PyInstaller 的 `sys.frozen` 会让 exe 弹不出卡片）；CI 的 `build.yml` 开头原本是 Python 三引号（YAML 解析不了，workflow 根本不会出现），改成 `#` 注释并给 Nuitka 带上 zhconv 词库；默认扫描间隔 30 分钟。
- **0.5.0（2026-10-10）**：轮询与菜单收简。扫描间隔改成固定 5/10/30/60 分钟四选一，去掉「随机 3~10 分钟」与 ±15% 抖动；移除托盘的「暂停轮询」子菜单（要临时停手就用「暂停本书 / 暂停此源」）；目录正序还是倒序的判定阈值提成 `config.json` 的 `order_trend_threshold`（默认 0.6），不再写死在代码里。
- **0.4.0（2026-10-10）**：拿真站跑出来的四个坑。① 只挂「下一页」的两页站以前永远看不到第二页——现在会跟着翻（只认同目录下的翻页链接）；② 「最新章节」改按目录排列取，站点把编号写乱时不猜编号；③ `notified_keys` 不再把还在目录里的章节忘掉（1600 章的书以前每轮都判「疑似重编号」，从此卡在 toc_reset）；刚开始多跟到一页时也不算重置。④ TLS 改用 Windows 系统证书库（新增 `truststore`），修掉「服务器少发中间证书」导致的 `CERTIFICATE_VERIFY_FAILED`——代理本来就是通的，卡的是证书链。书名显示也统一简体。
- **0.3.0（2026-10-10）**：入口收成一个——删掉 `shunshu add/list/check/history/interval/autostart/remove/source` 这些公开子命令（`shunshu` 只起托盘，`popup` 归内部），操作全在托盘右键菜单，配置只改 `data/*.json`。代理口径写清：**默认就走系统代理**（和浏览器同一套），`proxy` 只是给单个来源的覆盖；来源子菜单新增一行显示这一源实际生效的代理（手写覆盖 / 系统代理地址 / 直连）。
- **0.2.0（2026-10-10）**：一本挂多个来源。跨来源用 `match_key` 认同一章（繁简共通），已读与提醒按小说级合并，一本小说一张卡片、每行标出最先报它的来源；来源级 `proxy`（只认 `http://`、`https://`、`socks5://`，代理不通单记「代理不可用」，凭据不落盘）；托盘来源子菜单（设主源 / 暂停此源 / 删除此源）；卡片与菜单标题统一显示简体。`data/novels.json` 结构升到 `version` 2。
